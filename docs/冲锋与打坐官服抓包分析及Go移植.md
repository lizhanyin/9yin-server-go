### 3.5 关键结论

- **接近与冲刺是两段不同机制**：受理簇（含 msg707[15]）触发客户端自动
  接近（e 样本：簇到达与 state7 上报同毫秒）；最终冲刺由**服务端 c61 档1
  驱动**（客户端跑进 6.5m 冲刺距离时发放），不是纯客户端行为——
  「官服客户端自走」只对接近段成立。
- c1=17 伤害飘字 script 标签：锁定族=SkillLock、范围/普通=SkillNormal、buff=Buffer。
- msg205 锁定=单目标每段重发；范围=尾带全目标列表。
- msg707 族变体 [8/13/15/29]，15 固定出现在锁定/范围受理簇尾（方向型无）；
  语义未定位，按原样镜像（55964 会话实证缺它客户端不进入自动接近）。
- **受理与距离解耦**（f 十连按 14.6~19.8m 全受理零拒绝）；**玩家拉回不打断
  暂存**——服务端唯一出口是重按时的清除重铺，34s 往返零取消帧（f）。
- 走动段客户端/服务端分工（f 全程实证）：客户端 msg15 意图 id 区分自走
  （0xA000 前缀）与手动（0x3000/0x0000）；接近途中 ~6.2m 起以 msg220
  密报（~100ms 间隔），服务端据此在 ≤6.5m 发冲刺簇。

### 教训清单

1. 官服簇形态不可直接照抄——**官服客户端自走**是隐含前提，本服客户端需要服务端
   c61 主动驱动；
2. world 内部 NPC y 与广播 y 不是同一口径，任何用 y 差做判定的逻辑都会误判；
3. stagedRushFamily 的 script=="skilllock" 条件与本服 ini 实际列值（None）不符——
   判定应放宽为 `canRush`（lockSkill 判定本来就有 canRush 兜底）；
4. **「c61=瞬移」是误判**（2026-11-08 晚间更正）：56989 会话的瞬移实为当时与
   c61 同发的 **0x1F 终点锚**——官服 0x1F 只出现在 212 落地簇之后；c61 档1
   本身官服全程在用（客户端 350ms 冲刺到位），据此误撤全部 c61 导致「还是没跑」；
5. **受理簇方言错位**：msg26 首帧与 CurIsAirSkill=4 分别是重受理/空中方言，
   地面首发簇照发会破坏客户端自动接近（55964 会话零 state7 上报实证），
   且缺 msg707[15]。
