## 一、解码方法与合并规则

**帧格式**（游戏连接，三条线一致）：
- 线上字节 = 明文帧逐字节 `XOR(KEY=CC 3B 6D FA, i%4)` 后 0xEE 转义（`EE→EE 00`，帧尾 `EE EE`）；
- C2S `0x0A` custom 信封 = `0x0A | 16B session | u32 seq | TVarList(count u16 + [tag value]*)`；
- S2C `0x1E/0x27` = opcode + TVarList（无信封头）；TVarList tag：2=i32 3=i64 4=f32 5=f64 6=窄串 7=宽串 8=object(低32=对象ID, 高32=ownerID)。
- 属性名/线型取自 **c.pcapng 内带的 0x09 属性表（2433 项，t=0.09s 单帧 35KB）**；记录名取自 S2C `0x0A` 记录表（447 schema，c t=0.1s）。其余会话均中途开抓、无 0x09，按项目文档「7071/7074 双线表一致」使用同一回退表。

**时间线合并规则**（对应需求「一段时间内连续是同一个请求或请求应答则合并」）：
1. **请求-应答配对**：`C2S 0x18 ping → S2C 0x38`（0.6s 窗）、`C2S m924 → S2C m294`（1s 窗）、`m566↔m721` 令牌对；`m586/645/646/750` 四帧恒同拍，捆绑为「状态推送簇」。
2. **游程合并**：连续同签名事件、间隔 ≤3s → 合并为一段（×N，t0–t1）。签名含关键参数（技能名、msgId+子码、对象、记录/行列、属性名集合），保证「相同」判定有业务含义。
3. **周期通道聚合**：ping/延迟对、m9 握手、0x21 对象同步、0x28 批量帧、m54、m15 静止上报、状态推送簇等纯周期通道在骨干/精选视图中按会话聚合为计数行，全量视图仍逐段保留。
4. **不排除未知**：所有无法命名语义的帧均按原文（hex 头+长度+计数）进入时间线，并汇总于 §六。
