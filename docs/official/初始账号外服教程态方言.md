## 二、记录双通道方言（op14 → 0x11 / op29）

外服登录期对每个玩家记录**先挂载后推行**：

```
op14(12B): [0]=0x14 [1]=sub(0=玩家域, 2=全局 rec 273/276) [2:6]=obj [6:10]=owner [10:12]=rec u16
```

行体走两条通道，**按 schema 是否含字符串列分流**：

- **纯数字列 → 0x11**（与 Go serverRecordAddCells 同构）。如
  Task_Completed#31（52 行 × 1 i32 列，224B）、Repute_Record#44、
  cooldownbig_count_rec#111(58 行)、TiGuanRec#13(35 行)。
- **含字符串列 → op29 LZ 批量帧**（0x47 族压缩）。Task_Accepted#29(28 列)、
  Task_Record#30(15 列)、task_geog_rec#35、rec 84/100/112/142/149/158/159/172 等全部走此通道。

**op29 压缩帧头**（解压前可见的明文段）：

```
[0]=0x29 [1]=0x47(mode&2→头9B) [2:6]=len-1 [6:10]=outlen(解压长度 u32)
[10:12]=0 [12:13]=变体 [14]=0 [15:19]=obj [19:23]=owner [23:27]=rec u32
[27:29]=行数 u16 [29:]=LZ 位流（字面量内嵌可读串）
```

压缩本体是 fxnet2.dll RVA 0x1000 的 LZ77 式字典压缩（`tools/op28/lzdec.py` 可解），
但**字典池预置 .rdata DLL 静态串种子**（池表在 Themida 运行时解包区，静态读不到）——
首帧即回引 idx=0，纯静态复解需要动态调试拿种子；本包 20 个 op29 中仅 2 个
（无回引的）解压成功。Task_Accepted 行内容靠字面量内嵌串读出：`title_22096`、
`Transbron03*`、`target_*`、`contex*`、`Server`（列语义与 Go task49 行同构）。

**含义**：外服形态的 Task_Accepted 批量行**不可离线复刻**；等价通道 =
Go 现行 0x11 补零行（fork 方言，客户端已接受），或 mode=0x46 明文批量
（0x28 已实证客户端接受，0x29 未验证）。
