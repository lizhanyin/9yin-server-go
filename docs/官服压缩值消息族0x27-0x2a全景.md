# 官服压缩值消息族 0x27-0x2a 全景（2026-11-11 定案）

> **结论一句话**：0x27-0x30 族 = fxnet2 `ProcessMessage` 统一解压层（串表实证
> `(GameReceiver::ProcessMessage)decompress failed`）之下的**压缩容器**，
> 每 op 绑定一个业务处理器；四个主力 op 已全部行为学定名并走查：
>
> | op | 处理器 | 明文语法 | 语义 | 走查战绩 |
> |---|---|---|---|---|
> | 0x27 | **ServerRecordGrid**（批量单元格） | `[obj u16][own u16][row u16][00 02][u32][格数据]` | 记录单元格批量更新（含 base64 票据格） | 11 帧解出，(obj,own)≡相邻 0x1E 单格帧 |
> | 0x28 | **ServerAddObject** | `[obj u32][own u32][52B 变换块][n u16][[idx][列型值]×n]` | 场景对象物化（NPC/物件） | l 包 0x46 帧 6/6 精确；崩溃栈铁证 |
> | 0x29 | **ServerRecordAddRow**（批量行） | `[sub][obj][own][rec u16][flag2][rows u16][行×rows]` | 玩家记录行集批量预载（登录簇） | 139/235 精确；0x14 tag≡rec 闭环 |
> | 0x2a | **ServerObjectProperty** | `[obj u16][own u16=槽][row][181][08][[idx][列型值]×N]` | 对象属性更新（装备外观/槽） | 0x46 帧 16/16 精确 |
>
> 承接：`官服0x29批量预载通道解析.md`（0x29/0x2a 详案）、`官服模式NPC渲染收束.md`（0x28 崩溃史与 v3）。

## 一、客户端侧证据：fxnet2 处理器串表（新资产）

32 位 `adata/official/bin/fxnet2.dll`（VMP 只壳 .text，**.rdata 明文可读**）。
`tools/pcap_analysis/fxnet2_stringtable.py` 全提取（.rdata 0x2cd00-0x2f600 段）：

- **45 个 `Server*` 处理器**（串序）：EntryScene→ExitScene→AddObject→RemoveObject→
  SceneProperty→ObjectProperty→CreateView→DeleteView→ViewProperty→ViewAdd→
  ViewRemove→ViewChange→**RecordAddRow**→RecordDelRow→**RecordGrid**→RecordClear→
  Location→Moving→AllDest→LinkTo→LinkMove→Unlink→AllProp→**AddMoreObject**→
  RemoveMoreObject→ChargeValidstring→SetQR→SetVerify→SetEncode→Error→LoginSucceed→
  WorldInfo→Terminate→PropertyTable→RecordTable→Speech→SystemInfo→Menu→ClearMenu→
  Custom→Idle→Warning→FromGmcc→Queue→MsgTracert
- **内层读取原语**：RecvProperty / RecvRecordRow / RecvRecordGrid（"get message error"
  即带流读取失败——0x0B Out range 崩溃同源）
- **统一解压层**：`(GameReceiver::ProcessMessage)decompress size error / decompress
  failed / unknow message type` ⇒ 0x27-0x30 族在 ProcessMessage 层解压后按 op 分发
- **on_\* lua 事件**：每处理器对应 on_add_object / on_record_add_row /
  on_record_grid / on_object_property / on_add_more_object 等；on_\* 有 4 域变体
  （on_record_%s / on_view_record / on_viewobj_record / on_scene_record——对应
  0x29/0x14 的 sub 字段选域）
- x64 版 78 槽 vtable（NPC 收束文档）产物已佚；fxgamelogic 32 位版 .rdata 找到
  6 张 0x138(78槽) 间隔的 vtable 候选，但槽函数为薄转发无串直引——**op→槽位
  精确映射留作余项**

## 二、0x27 = ServerRecordGrid 压缩（批量单元格）

四包共 24+8+5+? 帧（mode 0x47 为主 + 0x46×3 同帧"c/k/l trsP1h1"）。明文头：

```
[obj u16][own u16(0x01xx/0x02xx 段)][row u16][00 02 恒定][u32 变长体长/类型][格数据]
```

- **(obj,own) 键与相邻明文 0x1E 帧逐对匹配**（0x1E = ServerRecordGrid 单格明文形态：
  `[1e][sub][obj u16=0x0200][own u16][col][len u32][值]`，实证帧带用户名 `lizy86\0`）；
  登录簇模式 = `0x1E×N（零散格）→ 0x27（同键批量压缩）`
- 样例形态三型：①base64 票据串（~250B，邻接 0x1E 带用户名——账号票据记录格）；
  ②稀疏 u32 id 数组（技能/任务 id 列表）③[idx][type][len][bytes] 混合格记录
- 走查器（tmp/pcap_analysis/op27_probe.py）11 帧解出；变长体精确语法未完全定版（余项）

## 三、0x28 = ServerAddObject（全景补充）

四包 22/290/220/18 帧。**官方 0x46 明文帧（仅 l 包 6 帧）走查 6/6 精确**：

```
[obj u32(0x0E____ NPC/物件域)][own u32(0x2a99/0x4412/0x4422…)]
[52B 变换块（与 v3 生成器一致）]
[n u16 @60][[idx u16][0x09 列型值]×n]   ← 字段区锚点: 首 idx 恒 179=CollideRadius
```

实测字段：CollideRadius / State / **Type** / **Resource** / RotatePara——NPC 对象
标准属性集。**c/k/登陆 的 0x47 帧（解出 21/238/17）走查全部失败**——解压输出在
锚点前损坏（池种子缺失），与 0x29 报告 §3.1 结论闭环：**LZ 精确重放不可行，
0x46 明文路径是唯一可靠通道**（v3 生成器即此路线，官方 6 帧先例已重新验证）。

## 四、0x29 / 0x2a（详见专案报告）

- **0x29 = ServerRecordAddRow 批量行**：明文 = 0x11 帧体去 op 字节
  （0x11=同处理器单行明文形态，16B 头双例精确验证）；**−0x18 规律**：
  压缩容器 op − 0x18 = 明文 op（0x29−0x18=0x11 铁证；0x2a−0x18=0x12、
  0x2c−0x18=0x14=ViewAdd 待验）。登录簇 `0x14 sub0 宣告 → 0x29 批量` 29 组。
- **0x2a = ServerObjectProperty**：装备槽对象属性（own=槽号 44-52 主装/4-22 子部位；
  ConfigID/UniqueID(GUID)/ArtPack/耐久/Ine\* 外观族/IneSetId 套装）。
