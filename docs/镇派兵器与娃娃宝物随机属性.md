### 2.6 机制结论（官方设计）

- 物品条目里**没有任何数值占位符**（无 0/-1、无"随实力等级"标记字段）；动态性完全由属性包行末的**条件 ID** 表达。
- 四条属性的值 = 玩家当前 **PowerLevel（实力等级）** 命中哪个条件行，就取该行数值——**评估是活的**，角色变强后命中行自动上移，物品本身不存值。这就是"给与时根据角色强度临时赋值"的官方语义。
- proppack 还支持公式值（同文件其它包示例：`r=,MaxHPAdd,131$-PowerLevel$*450,0,201448`，`$` 包裹玩家属性名的表达式），本组 8 个包未用到公式、全是常量行。
- 服务端若选择"发放时快照"，等价于按当时 PowerLevel 命中行把值固化进实例；若选择"活算"，则在面板聚合时按当前 PowerLevel 现取行。两种的差距=发放后角色升档是否自动涨。

### 2.8 攻略两个实力点数分析的核验（对 varprop NeiGongLevel 硬数据）

|---|---|---|
| 三内36层=67=(6×6)+31 | 67（基准=首层32=31+1 ✓） | ✓ |
| 四内49层=90=(7×7)+41 | 90（首层42=41+1 ✓） | ✓ |
| 江湖49层=81=9×9 / 64层=100=10×10 | 81 / 100 | ✓ |

"75 层对应几内"之争的官方答案：江湖 75 层=122 点，介于门派五内(111)与六内(131)之间、更靠近六内。公式框架（n²+基准）本质是对逐层表的拟合——真实机制就是 varprop 每层一行 NeiGongLevel，无 closed-form。

### 3.5 娃娃成长经济：淬炼 / 强化 / 升品 / 套装（消耗与公式）

> 本节全部表格在 `share/rule/randomequiprule/newtersure/`，语义经客户端 UI 代码反证（`lua64/form_stage_main/form_life/form_newtreasure_grave.lua` 1646 行主表单 + `form_newtreasure_intensify.lua` 强化弹窗 + `custom_sender.lua`）。

#### 3.5.1 淬炼消耗曲线 —— newtreasurecost.ini（442 行，UI 代码实证）

**机制**（grave.lua:572-667 `on_btn_grave_click`）：淬炼 = 重掷附加属性候选。费用按**玩家当日已用整银淬炼次数 N**（玩家属性 `NewTersureCount`，UI 文案"其价格会随当日使用整银淬炼次数增长不断递加"→ **每日重置**）递增，单次淬炼花费 `cost(N)`：

| N（当日第几次） | cost(N) | 递增量 |
|---|---|---|
| 0-99 | 200×(N+1)，即 200→20000 | 每次 +200 |
| 100-199 | 22000 + 2000×(N−100)，即 22000→220000 | 每次 +2000 |
| 200-299 | 240000 + 20000×(N−200)，即 240000→2220000 | 每次 +20000 |
| 300-399 | 2400000 + 200000×(N−300)，即 2400000→22200000 | 每次 +200000 |
| 400-437 | 24000000 + 2000000×(N−400)，即 24000000→98000000 | 每次 +2000000 |
| ≥438（超出表） | `[Special] r=100000000` 每次固定 **1 亿** | — |

即**分段线性**：每 100 次单价跳一个数量级，`[Normal]` 节键 0-437 共 438 档，越界读 `[Special]`。

**支付规则**（grave.lua:647-657）：
- 单次淬炼（sel_count=1）：优先消耗 1 张**翡翠娃娃淬炼券**（物品 `newtreasure_grave`，`goods_grid:GetItemCount("newtreasure_grave")` 计数；名俊每日勤修苦练礼包送免费券）；
- 无券 或 五连淬炼（UI"淬炼十次"按钮实际 `revise_count=1→sel_count=5`，即**五连**）：按上表银两（`ui_newtreasure_cost` 文案配 `money\yyb.png` 图标）计价，费用=Σ cost(N..N+4)。

#### 3.5.2 附加属性强化（升等级）—— addpropexp.ini（10 行）+ addproplevel_1..4.ini

**强化**（intensify，弹窗 form_newtreasure_intensify.lua）= 把某条附加属性从 k 级升到 k+1 级，数值区间从 `addproplevel_<品质>.ini [propID] k=min,max` 换到 `k+1=min,max` 重掷。客户端展示逻辑（intensify.lua:95-168）实证的查表链：

- 玩家经验池 = 玩家属性 **`NewTersureValue`**（UI 顶部直接 QueryProp 显示）；
- 等级上限 = `addpropexp.ini [Limit] <物品Level>=<上限>`，当前仅一行 `56=10`（56 级娃娃附加属性最高 10 级）；到达上限时 UI 拒绝（grave.lua:1143-1161 比对 `revise_power==Limit`）；
- `[Exp] 1=10 / 2=40 / 3=100 / 4=400`：客户端 Lua **不读此节**（全资源仅 [Limit] 被 3 处引用）→ **服务端侧消耗表**，键 1-4 疑按品质档（revise_level）收每次强化经验，语义待服务端实现/抓包实证；
- `[Replace] Ratio=0.8`：替换附加属性时的经验折算系数（保留/返还 80%），同为服务端语义。

**品质与数值对照**（addproplevel 系列，[propID] 节、行 `1=min,max`…`10=min,max`）：品质 1→4 数值区间逐级放大（如 [0] 气血上限：品质1 `1=12,200…10=98,680`，品质4 `1=30,1600…10=246,5440`）。品质本身由 §3.3 第 6 步 addproprule `[Color]` 千分 roll 决定，另有**升品服务**：玩家属性 `NewTreasurePropColorUpLimite > 0` 时可用（grave.lua:185，每角色一次，需已淬出 5 条附加属性且存在非玉品级条，`tips_newtreasure_up_1` 全条件）。
