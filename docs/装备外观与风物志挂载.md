## 二、风物志皮肤挂载（V3）

**游戏内真实流程**：卡片道具（`card_item_*`，script=CardItem，`CardID` 字段直连皮肤号）在背包 → **使用后收录**进风物志（衣橱）→ 在衣橱里**换装**。服务端两条上行链路 + GM 直通链路都已实现：

| 环节 | 实现 |
|---|---|
| 数据源 | `SkinCatalog`：客户端资源 `rule/card.ini`（1239 张：Weapon 348 / Cloth 247 / Hat 133 / Waist 101 / Cloak 57 / Mount 31 …），ModelData=`部件,模型;部件,模型` 多段；Latin-1 无损读 |
| 卡片 ↔ 皮肤映射 | `ToolItemCatalog`：tool_item.ini `[card_item_*].CardID`（如 card_item_10001↔皮肤1 屠龙刀鞘）；`cardItemBySkinId(skinId)` 反查 |
| **使用收录（C2S 31）** | `handleBodyItemUse`：USEITEM **恰好 4 值** `[31, view, slot, count≥1]`（menu2.exe `USEITEM fwz card %s (view=%d pos=%d)` + `reject malformed native item use values=` 钉死；早前挂 30 是误判——30 是纯 MOVEITEM 移动物品）。按 (view,slot) 命中背包行分流：装备→右键穿（`wearFromBag` 自动槽）、CardItem→`consumeBagItem` 消耗 1 张收录（不自动挂载）、其余类型记日志钩子 |
| **衣橱换装（C2S 180）** | `handleWardrobeCard`：lua64 钉死子操作方言 `CustomSend(180, sub, card_id)`——sub 0=USE 挂载（须已收录；同部件互斥替换：武器换武器/衣服换衣服，发型等异部件叠加）、sub 1=CANCEL 卸下、sub 7=COLLECT 收录（背包有对应卡片则消耗 1 张）；其余 sub（2 武技/3 兑换/5 替换/6 显隐/8 领奖/12 套装）记日志待接 |
| 状态存档 | `SkinStore`：data/skins.json 主档 + MySQL `role_skins`（admin/sql/0006 迁移；attachDatabase 建表兜底）双源，CustomizingStore 同款 |
| 协议帧 | `SkinMessages`：收集 = `CardRec[3]` 位图（32 皮肤/行，**serial=皮肤号+1**——皮肤 1=行 0 位 1、31=行 0 位 31、32=行 1 位 0，与 Task_Completed/引擎 FxGameLogic 位判定同式，2026-11-06 修复错位 1bit 后真机解锁）；挂载 = `UseCardRec[2,2]`（皮肤号 + 显示类型 0）追加行、0x12 倒序删行；显示开关 = `ShowEquipType`(408,byte=2) + `CardID` 属性帧 |
| 整刷方言 | 增量更新先删旧行再整刷（追加方言下重推会追加成新行）；`skinRefreshFrames` 统一编排：清位图行 → 推位图 → 清挂载行 → 推挂载 → 显示开关。**不发 custom 180**：S2C 180 是子操作分发（lua64 on_card_msg：0 开兑换窗/1 开替换窗/2 开收录窗/3 收录回执 show_request_reason(arg2=is_show 0..3)/4 武道购买刷新），裸皮肤号会被当 opt_type 误开窗——收录状态由 CardRec 记录帧驱动 CollectCardManager(IsGetCard)+data_binder 刷新 |
| GM 直通 | `equip_card{cardId}`（未收录自动补收录+挂载）、`unequip_card`（清挂载留图鉴）、`grant_all_cards`（全量收录）——GM 网页直接挂载，不用点背包收集（F 服口径） |
| 登录恢复 | ClientReady 链（键位推送后）：`pushSavedSkins` 推已存收集位图 + 挂载行 + ShowEquipType；无存档零帧 |
| 时装页签 | `grant_all_fashion`：全部 `EquipType=FashionCoat`（525 套）→ role_fashion_suits + `FashionSuitRec` 行（登录恢复同推）+ data/新版服装数据.json 存档 |

## 四、真机校准点（无官方抓包，按 GM 面板口径实现）

1. ~~C2S 30 / C2S 180 载荷布局~~：**30/31 已钉死**（menu2.exe 字符串 + bak 反汇编三方证据，见 `docs/go-source-protocol-notes.md` §7.3）——30=`[fromView,fromSlot,toView,toSlot]` 纯移动、31=`[view,slot,count]` 使用链；~~180 仍整型记录待真机校准~~ **180 已钉死**（lua64 client_custom_define/form_card:41-43/form_collect_card:496/form_attire_card:216）：C2S=`[180, sub, card_id]`（0 USE/1 CANCEL/2 USESKILL/3 EXCHANGE/5 REPLACE/6 IS_SHOW/7 COLLECT/8 GETAWARD/12 套装），S2C=子操作分发（见上表整刷方言行）。
2. `UseCardRec` 第二列语义（暂发 0）；装备武器卡后看人物手模是否变化，不动则试发 subtype。
3. 运行时 0x10 推 Cloth/Pants/Shoes 是否热刷新；不刷新改走 `Fashion*` 通道。
4. 时装槽 16-19 与类型的对应——**V4 已由 lua64 UI 绑定表钉死**：16=Suit(身份装) / 17=FashionCoat / 18=FashionHat / 19=FashionShoes，新面板镜像 40-43（form_new_rp_arm.lua:848-881）。
5. `FashionSuitRec [7,3,3,4,3,3]` 数值列语义（暂零填充）。
6. **CardRec 位图 serial（2026-11-06 已钉死）**：`[3]` 记录引擎侧按位读，serial=id+1（皮肤 0=行 0 位 0、皮肤 1=行 0 位 1…与 `TaskMessages.completedBit`/Go 参考服 `taskCompletedBit`「modern FxGameLogic predicate」同式）。曾用 serial=id（皮肤 1=行 0 位 0）整体错位 1bit → 真机「使用了没解锁」。
   以上均为单点常量/单方法内可改。

### V4 真机校准点

1. **穿戴自动切换显示类型**（穿时装→2、穿身份装→1）是本服口径——官方可能只换装不切模式，真机点一次「穿上」看是否跟随 radio；不跟随则删 `wearFashionSuit` 里的 `saveShowEquipType`。
2. Cloth/Pants/Shoes/Hat 主通道 vs FashionCoat/Hat/Shoes 镜像通道哪个驱动渲染（现双发；lua 证据倾向主通道=最终模型 + ShowEquipType）。
3. 身份装整套模型下发后 `_h` 伴随件（cloth_h 连体帽隐藏发型）是否需要服务端额外挂（form_roles.lua:575 线索）。
4. custom 19 sub2 的槽名实参大小写（lua 传 EquipType 原文，已大小写不敏感映射槽位）。
5. 购买扣 1 金为会话级扣减（货币落库属货币持久化专项）；余额不足现仅日志拒绝，客户端无失败回执通道（待真机找拒绝下行）。
