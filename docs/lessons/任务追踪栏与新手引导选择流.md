# 避坑：任务追踪栏与新手引导选择流

> 来源：2026-11-26 排查「任务栏不显示任务」、落地引导选择流（初出茅庐／再战江湖）。
> 细节见 `docs/official/NPC任务绑定与引导流任务协议定版.md` §七；
> 选择窗触发帧的定版见 `docs/verified/新手引导选择窗触发帧m427.md`（2026-11-27 真机已验证）。

## 抓包分析

- **帧首 6 字节解成零、消息“消失”**：重组器没按 IP 头总长截断，纯 ACK 的以太网零填充被当成载荷，同 seq 的真数据被当重传砍头。已修（`trimIPTotal`）。帧解出全零或非法 op，先怀疑重组，不要先发明协议——此前文档里的“7 字节带外标记”就是这个伪影。
- **端口与方向**：不是每份抓包都是 8032（男号包服务端口是 7114）。先列会话确认哪边是服务端，再看帧。
- **`cut -c` / `grep -v` 会截掉、滤掉关键帧**：截断 hex 输出丢过一个 `00`，滤噪声时差点漏掉 `m972`。取证时全量输出，过滤只用于浏览。
- **消息号别心算**：972 是 `cc 03 00 00`，心算成 `ca 03` 就搜不到。用程序算。
- **文档说“没有”不等于没有**：文档记“跳过引导-男流抓包没有”，资料目录里其实有，而且就是跳过那一下的完整实录（当时误判成“跳过后的再登录”）。先 `ls` 资料目录，再下结论。
- **「加壳 DLL 查不到绑定表」不成立**（2026-11-27 订正）：此前读不出引擎的消息号与处理函数的绑定，只好从抓包和客户端文案反查（`ui_SPYD_info` → `form_single_blackback` → `m972`），结果把属性 idx225 当成了弹窗门控、漏掉了触发帧 m427。加壳只挡静态读：弹窗时的内存 dump（堆上的分发表）和脱壳镜像的静态表都读得出来，下标就是消息号。查某个消息号对应哪个 lua 函数，先读表（`docs/verified/s2c-custommsg-handler-table-*.tsv`）。
- **压缩批帧别用模拟解码器下结论**（2026-11-28）：官服把大消息经 fxnet2 LZ 压进 op 0x27–0x30 批。模拟解码器（`lzdec2.py` 一族）在 m414 sync 帧上撞了池位（`02 30 00 00` 这类窗口哈希到 1 号池位，顶掉段首匹配源），解出 274 个垃圾值，差点据此认定官服表里没有语音开关。标准答案用**客户端 dll 的真解码器**取：ctypes 载入 `fxnet2.dll`，按 RVA 0x11f0 的签名喂 blob，池跨帧共享所以要从连接头按序喂，遇池缺失即停（`tmp/npctalk/reallz.py`）。普通明文帧 `wiredec.py` 显示串型参数也会错位，判帧内容要 hexdump。
- **开关号也别心算**：闸门常量 `0x5e5` 是 1509，我一路当成 1517（`0x5ed`），在解出的表里搜 1517 搜不到、白绕一大圈。

## 对拍与测试

- **期望值不手抄**：这次手抄的期望值错了 4 处——十进制换算（`0xF8000000` 是 4160749568）、过滤后漏了零值行、帧号用了工具修复前的编号、键名打错（`caji`，官服是 `caiji`）。期望值从抓包程序化导出；字节对拍测试要写，它能兜住这类错。
- **“余额”不是“增量”**：历练第 5 档官服写 33000，增量是 32000，差的 1000 是新号登录基线。奖励类数值先查登录时的基线。
- **定时器用例偶发失败**：定时器协程里首次触发懒加载（NPC 目录冷加载，`-race` 下超过 5 秒），超出等待预算，协程还泄漏到下一个用例。做法：用例里先预热懒加载；帧收集器带锁；`GOMAXPROCS=1 go test -race` 能把时序类偶发变成必现。
- **复用同包 helper 前先看口径**：`mustHex` 不收带空格的 hex。

## 客户端与排障

- **数据对但 UI 不显示，查窗体生命周期**：任务行、标记帧都对，追踪栏仍不显示——窗体进场时被预载成隐藏，只有 `m390` 才显示。排“不显示”先找谁负责显示，再查数据。
- **「引擎控制的 UI 弹不弹，服务端只能对齐输入」错了**（2026-11-27 订正）：黑幕窗是服务端 m427 显式请求弹的，真机已验证（`docs/verified/新手引导选择窗触发帧m427.md`）。「对齐官服帧」要对到触发帧——办法是拿有、无该现象的两类会话对比 op09 之后的帧，而不是只找看起来相关的属性帧。超时兜底和 GM 入口仍然保留。
- **0x0B 前的 0x10 到不了场内玩家对象**（2026-11-28）：进场会重建玩家对象，场内属性只认 0x0D 物化帧的属性区（引擎「建对象时即读」）。官服在 0x0B 前用 0x10 单发过的属性，0x0D 属性区里全部重发一遍——`HelpStepID` 就在其中。本服只在 0x0B 前单发过 `HelpStepID`，客户端读到的恒为空，`movie_end_callback` 首段即返回，五个会话零 m950。**m414 gamestep 要留在 0x0B 前（引擎全局态，迟到黑幕窗不弹），但 0x10 属性要补在 0x0D 之后**——两者不是一回事，别因为「引导簇必须在 0x0B 前」就把属性也只发在那儿。
- **「同客户端连别服正常、连本服不正常」＝服务端少发了东西**（2026-11-28）：NPC 语音这条我先归因到「AOW 安装没有 snd.package」，是错的——用户一句「同一个客户端连官服有语音」就否掉了。这种情况直接去找**触发链入口的闸门**：NPC 语音的闸门是 `CheckSwitchEnable(0x5e5)`，而整张开关树本服从未下发（m414 `["sync", …]`）。
- **配置文件里有键 ≠ 客户端还在读它**（2026-11-28）：`freshmanhelp.ini` 每步都带 `tip=`、`textinfo=`、`tipTime=`，我顺着它找「引导提示」找了好几层（`auto_show_form`、引擎 dll 字符串）；其实在现行客户端 2297 个 lua 字节码和所有 dll 里这些键零引用，早就死了。现行提示走另一套（m371 帮助窗）。**判断一个键是否还活着，先在客户端现行字节码常量里全文搜**（解包工具 + `grep -a`），再读逻辑；别从配置文件的注释出发推实现。读 lua 也要用客户端**现行包**解出来的那份（这次用 unluac 复核了旧反编译树恰好一致，下次未必）。
- **按消息号回查 handler 表，别按变量名搜 handler**（2026-11-28）：我在 lua 里搜「谁调 `open_helper_form`」，搜到 `on_jianghu_guide`，一查表是 372，于是满抓包找 m372、还去解压缩批——当然找不到。官服帧里真正的消息号是 371（`02 73 01 00 00`），对应 `on_new_player_guid`。两个 handler 都通向同一个开窗函数，搜调用点会同时命中。**先从帧里读出号，再按号查表**。
- **「没有 X」要先定位卡在第几环**（2026-11-28）：用户说「引导提示没有」。抓包一看 m950 已经通了（上一轮修复生效），卡点后移到了 1347 发书之后——官服那里紧跟一帧 m371。把本服和官服的时间线并排拉出来，第一条分叉点就是答案；不要回到「引导提示」这个词的最宽泛含义上去找。
- **官服帧位是事实，放在哪是产品口径**（2026-11-28）：操作模式引导（m704）官服在选择窗弹出的那一拍发。首版照抄官服位，真机出窗后用户要求「移到剧情演出后，选择再战江湖的也要发」。对齐官服解决的是「有没有」；「放在哪」要按用户看到的流程定。两条线说的同一件事（剧情演出）在帧上不是同一处——初出茅庐线是 1340 接取影像，再战江湖线根本没有影像——各找各的落点，别硬凑一个条件。
- **单跑绿、全量偶发红，先看多出来的帧是谁发的**（2026-11-28）：新增 8 个用例后影像用例全量 9 次红 3 次，帧列表里多一帧零参 `m26`。是既有用例起的选靶看门狗（5 秒后发 `m26`）比用例活得久，新增用例把后面的用例整体推后几百毫秒，它正好落进对帧数做精确断言的用例。修法：时长提成变量（`npcSelectWatchdog`），测试服构造时调长——同技能夹具「作废遗留定时器」的思路。包级观察器会把任何人的帧记到当前用例名下。
- **「每角色一次」的标记要落档**（2026-11-28）：靠会话态标记，选择后那一秒里掉线重登就再也收不到；roleState 加一个 `omitempty` 布尔字段最省事，旧档缺省 false。

## 协作与环境

- **并行会话改同一文件**：Edit 会因文件已变被拒，重读后再改，只留最小改动。
- **模块内别留临时 Go 程序**：`tmp/` 下的 `main` 包会进所有人的 `go build ./...`，用完即删。
- **`cd` 会带走后续命令的工作目录**：命令里用绝对路径。
- **编 exe 前先看线上那份含谁的未提交内容**（2026-11-28）：线上 exe 是别的会话从共享树编的，含他们当时未提交的 `appearance.go`；等我要编时那个文件又被改过（还没上线）。直接从共享树编会把人家没上线的半成品带上线，干净导出又会把人家已上线的回滚——取「线上那一刻」的版本（按当时的 `git diff` 复原）叠进干净导出。所以看到别人的未提交改动时要随手把 diff 留档，过几小时它就不是原来那份了。
